# Спецификация фичи — Кастомная цифровая клавиатура (P2P Amount Input)

## 1. Цель
- Предоставить встроенную цифровую клавиатуру для ввода суммы перевода без системной клавиатуры.
- Используется на экране ввода суммы.
- Ограничение: текущая клавиатура поддерживает только цифры `0-9`, запятую `,` (без бизнес-действия) и удаление `⌫`.

## 2. Состав интерфейса
| Элемент | Обязательный | Описание |
| --- | --- | --- |
| Контейнер клавиатуры | Да | Блок из 4 строк и 3 колонок |
| Кнопки цифр | Да | Кнопки `1-9`, `0` |
| Кнопка удаления | Да | Кнопка `⌫`, удаляет последний символ |
| Кнопка запятой | Да | Кнопка `,`, сейчас без действия |
| Визуальная подсветка нажатия | Да | Полупрозрачная подложка + масштабирование |
| Хаптика на touch down | Да | Тактильный отклик на нажатие кнопки |

## 3. Термины
| Термин | Определение |
| --- | --- |
| touch down | Момент касания кнопки пальцем |
| touch up inside | Отпускание пальца внутри границ кнопки |
| Press Down анимация | Фаза визуального «нажатия» кнопки |
| Release анимация | Фаза возврата кнопки в исходное состояние |
| productive | Каноническая кривая для micro interactions (по motion-правилам) |

## 4. Правила поведения
### 4.1 Базовые правила
- Сетка кнопок фиксированная: 4x3.
- Раскладка по строкам:
  - `1 2 3`
  - `4 5 6`
  - `7 8 9`
  - `, 0 ⌫`
- Нажатие на цифру добавляет одну цифру в конец строки суммы.
- Нажатие `⌫` удаляет последний символ, если строка не пустая.
- Нажатие `,` не меняет сумму.

### 4.2 Граничные случаи
- При `⌫` на пустой строке изменений нет.
- Ограничение максимальной длины суммы отсутствует.
- Повторное удержание `⌫` (auto-repeat) отсутствует.

### 4.3 Что запрещено
- Нет multi-touch логики для одновременного ввода несколькими пальцами.
- Нет disabled-состояний кнопок.

### 4.4 Хаптика
- Хаптика срабатывает на `touch down` каждой кнопки.
- Тип: `rigid`.
- Интенсивность: `0.6`.
- Подготовка генератора выполняется при инициализации и после каждого `impactOccurred`.

## 5. Взаимодействие и жесты
### 5.1 Состояния кнопки
- `idle`: `scale = 1.0`, `highlightOpacity = 0.0`.
- `pressing`: идет Press Down анимация.
- `pressed`: визуально увеличенная кнопка в конце Press Down.
- `releasing`: идет Release анимация.

### 5.2 Переходы состояний
- `idle -> pressing`: при `touch down`.
- `pressing -> pressed`: после завершения Press Down.
- `pressed -> releasing`: при `touch up inside` или `touch cancel` после завершения Press Down.
- `pressing -> releasing`: если палец отпущен раньше, Release откладывается до завершения Press Down.
- `releasing -> idle`: после завершения Release.

### 5.3 Пороги и условия
| Условие | Результат |
| --- | --- |
| `isPressed = true` | Запускается Press Down; вызывается `onPress` один раз за одно касание |
| `isPressed = false` до конца Press Down | Ставится флаг release, Release стартует после окончания Press Down |
| `isPressed = false` после Press Down | Release стартует сразу |

## 6. Движение и анимация
### 6.1 Атрибуты анимации
| Триггер | Свойства | Длительность | Кривая |
| --- | --- | --- | --- |
| `touch down` | `scale: 1.0 -> 1.2`, `highlightOpacity: 0.0 -> 0.1` | `150 ms (fast)` | `productive` |
| `touch up inside/cancel` | `scale: 1.2 -> 1.0`, `highlightOpacity: 0.1 -> 0.0` | `150 ms (fast)` | `productive` |

### 6.2 Конфигурируемые motion-параметры
- `downDuration = 150 ms`
- `upDuration = 150 ms`
- `pressedScale = 1.2`
- `releasedScale = 1.0`
- `pressedOpacity = 0.1`
- `releasedOpacity = 0.0`

### 6.3 Переходы (шаги)
#### `idle -> pressing -> pressed`
1. На `touch down` запускается анимация увеличения/подсветки.
2. В этот же момент триггерится хаптика.
3. После 150 ms состояние фиксируется как `pressed`.

#### `pressed -> releasing -> idle`
1. На отпускание кнопки запускается возврат масштаба и подсветки.
2. Если отпускание произошло раньше конца Press Down, Release ждёт завершения Press Down.
3. После 150 ms кнопка возвращается в `idle`.

## 7. Геометрия и ограничения
### 7.1 Типографика
- Текст кнопки: `.title`, `bold`, `rounded` design.
- Практический кегль при стандартном Dynamic Type: около `28 pt` (зависит от системных настроек).
- Цвет текста: `#333333`.

### 7.2 Размеры и отступы клавиатуры
- Сетка: 4 строки x 3 колонки.
- Межкнопочные отступы по горизонтали: `0`.
- Межстрочные отступы по вертикали: `0`.
- Внутренний padding у контейнера клавиатуры: отсутствует.
- Фоновая подсветка кнопки: rounded rectangle, `cornerRadius = 100`, ограничение `maxWidth = 80`, `maxHeight = 70`.
- Контейнер контента кнопки: ограничение `maxHeight = 80`, `maxWidth = infinity`.

### 7.3 Поведение ширины и высоты при изменении экрана
- Ширина клавиатуры равна доступной ширине родительского контейнера (`W`).
- В каждой строке 3 кнопки, каждая получает равную ширину: `keyWidth = W / 3` (при `spacing = 0`).
- Минимальная ширина кнопки не задана; на узких экранах кнопки сжимаются пропорционально.
- Фиксированная высота ряда не задана; задан только верхний предел (`maxHeight = 80`) для кнопки и (`maxHeight = 70`) для подложки.
- Итоговая высота клавиатуры равна сумме высот 4 рядов и не имеет отдельного жёсткого констрейнта.
- Клавиатура учитывает safe area снизу (игнорирование safe area не используется).

### 7.4 Интеграция в экран ввода
- Клавиатура расположена последним элементом вертикального стека экрана.
- Дополнительный нижний padding к клавиатуре не задан.
- Расстояние до нижней грани физического экрана определяется только safe area устройства.

## 8. Наблюдаемые факты и допущения
### 8.1 Наблюдаемые факты
- `,` присутствует в UI, но бизнес-действия у клавиши нет.
- Визуальный отклик клавиши всегда выполняется в две последовательные фазы `down -> up`.
- Хаптика запускается на `touch down`, а не на `touch up inside`.

### 8.2 Допущения
- Для handoff кегль кнопок интерпретируется как эквивалент `.title` (динамический размер, не жестко зафиксированный в pt).
- Кривые анимации в спецификации нормализованы до `productive` по ruleset micro interaction.

## 9. Риски и открытые вопросы
- Нужна ли фактическая функциональность клавиши `,` (ввод дробной части)?
- Нужна ли фиксированная высота кнопки/ряда (например, `80`) вместо текущего `maxHeight`?
- Нужен ли auto-repeat для `⌫` при удержании?
- Нужен ли лимит максимального числа символов ввода?
- Нужно ли отключать Dynamic Type-влияние на кегль клавиш для стабильной геометрии?
- Нужна ли отдельная адаптация для landscape и split-screen режимов?
